# Reproducibility Guide

This document provides instructions for reproducing or verifying Q-Grid's
research results **without re-running the canonical experiment**.

## 1. Environment Setup

```bash
# Create and activate a virtual environment
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# Install all pinned dependencies
pip install -r requirements.txt
```

Pinned versions (from `requirements.txt`):

| Package | Version |
|---|---|
| qiskit | 2.6.0 |
| qiskit-aer | 0.17.2 |
| ortools | 9.15.6755 |
| numpy | 2.5.4 |
| scipy | 1.18.1 |
| pandas | 3.0.6 |
| matplotlib | 3.11.2 |
| pytest | 9.1.1 |

> **Note:** `qiskit-aer==0.17.2` cannot be imported on Ubuntu 26.04 runners
> due to a `libgomp` static TLS block error. On such systems, the 10
> Aer-dependent tests are skipped via `pytest.mark.skipif`.

## 2. Running the Statistical Review (Non-Destructive)

The statistical review script (`statistical_review.py`) reads the **canonical
experiment JSON** and writes its outputs to
`results/noise_sensitivity/review_20261023/`. That directory already
contains files from the original review run:

- `01_paired_gap_differences.png`
- `02_bootstrap_effects.png`
- `03_paired_scatter.png`
- `paired_differences.csv`
- `bootstrap_summaries.csv`
- `reproducibility_gaps.md`
- `statistical_review.md`

**Running the script as-is will overwrite these existing files.** The script
does include a self-integrity check (lines 727–729) that verifies the input
JSON was not modified, but it does **not** back up prior output files.

### Safe approach — back up first:

```bash
# Back up existing review artifacts
cp -r results/noise_sensitivity/review_20261023 \
      results/noise_sensitivity/review_20261023_backup

# Then run the review
python statistical_review.py

# Compare outputs
diff -r results/noise_sensitivity/review_20261023_backup \
      results/noise_sensitivity/review_20261023
```

### Non-destructive alternative (proposed):

To run the review into a **separate** directory without touching existing
files, set the `REVIEW_DIR` environment variable before running:

```bash
# Run review into a timestamped directory (does not use the env var
# directly — this is a proposed workflow modification for future approval)
#
# For an immediate non-destructive run, copy the script:
cp statistical_review.py /tmp/statistical_review_copy.py
# Edit REVIEW_DIR in the copy to a new path, then:
python /tmp/statistical_review_copy.py
```

> **Do not run `python statistical_review.py` directly** until the back-up
> approach above has been applied, or the non-destructive copy method is
> confirmed.

## 3. Inspecting Existing Results (No Computation Required)

### Canonical Experiment JSON
```
results/noise_sensitivity/20261023_122432_noise_experiment.json
```
- 240 trial records (6 instances × 4 noise conditions × 10 seeds)
- MD5: `28b7039a759818152565f295a1ee4ff6`

This file is **read-only** — neither `statistical_review.py` nor
`noise_analysis.py` modifies it. Both scripts contain assertions verifying
the JSON was not altered during the review pipeline.

### Pre-existing analysis outputs

| Directory | Script | Contents |
|---|---|---|
| `results/noise_sensitivity/analysis_20261023/` | `noise_analysis.py` | Aggregate CSVs, analysis report, audit report, plots |
| `results/noise_sensitivity/review_20261023/` | `statistical_review.py` | Paired-difference CSV, bootstrap summaries, review report, plots |

### Provenance manifest
```
results/noise_sensitivity/PROVENANCE.md
```

Documents experiment configuration, exact package versions, instance set,
and known limitations. Key provenance note: the canonical JSON does **not**
contain a `provenance` key — it was generated by an earlier version of the
code. Future runs (commit `5a3c0af` or later) will include a `provenance`
object with git commit, Python version, OS platform, package versions, seed
configuration, and Aer/optimization parameters.

```bash
python -m pytest tests/ -v
```
